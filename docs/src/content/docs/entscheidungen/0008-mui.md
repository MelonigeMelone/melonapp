**Status:** angenommen · **Datum:** 2026-11-11

## Kontext

Die erste Web-App war mit eigenem CSS gebaut. Die nächsten Schritte bringen deutlich mehr
Oberfläche: Notfall-Kit-Dialoge, Einstellungen, Desktop-App, später TOTP und Teilen.
Dafür braucht es Dialoge, Menüs, Snackbars, Tooltips und Tabs, die zugänglich sind und
überall gleich aussehen.

## Entscheidung

**MUI (Material UI) 9** mit einem eigenen Theme (`apps/web/src/theme.ts`):

- Farben, Schriften und Formen der Wassermelonen-Gestaltung stecken im Theme. MUI-Komponenten
  sehen dadurch nach MelonApp aus, nicht nach Google.
- Hell/Dunkel über `colorSchemes` und CSS-Variablen (`colorSchemeSelector: 'class'`). Standard
  ist „wie System“; unter „Konto“ lässt sich hell oder dunkel festlegen (MUI merkt sich das im
  `localStorage`). Die Klasse setzt MUI vor dem ersten Zeichnen, die App rendert ohnehin erst mit
  JavaScript. Ein Skript im `<head>` wäre wegen der CSP (`script-src 'self'`) nicht erlaubt.
- Eigene Farben (`palette.melon.*`) für Schale, Frucht, Ziffern und Sonderzeichen.
- Eigene Typografie-Variante `password` für die Passwortanzeige.
- Der Tresor-Bildschirm wird nachgeladen (`React.lazy`), damit die Anmeldeseite schnell da ist.

### Folge für die Content-Security-Policy

MUI nutzt Emotion. Emotion erzeugt CSS zur Laufzeit und schreibt es in `<style>`-Elemente.
Die CSP erlaubt dafür jetzt `style-src 'self' 'unsafe-inline'`.

Warum das vertretbar ist:

- **Skripte bleiben streng** (`script-src 'self' 'wasm-unsafe-eval'`). Eingeschleustes CSS
  kann keinen Code ausführen.
- Der klassische Datenabfluss per CSS (Attribut-Selektoren mit `background-image: url(…)`)
  ist blockiert, weil `img-src`, `font-src` und `connect-src` nur die eigene Domain erlauben.
- React escapet alle Inhalte. Nutzerdaten landen nie als HTML oder CSS in der Seite.

## Alternativen

- **Eigenes CSS beibehalten:** kleinste Bundle-Größe und strengste CSP, aber jede Komponente
  muss selbst gebaut und zugänglich gemacht werden.
- **Pigment CSS** (MUIs Engine ohne Laufzeit-CSS): würde `'unsafe-inline'` überflüssig machen,
  ist aber noch in Version 0.0.x. Für einen Passwortmanager zu früh.
- **CSP-Nonces:** bräuchten pro Anfrage erzeugtes HTML. Die Web-App ist bewusst statisch.

## Folgen

- Die Anmeldeseite lädt etwa 151 KB JavaScript (gzip), der Tresor weitere 38 KB, dazu das WASM (106 KB).
  Vorher waren es 76 KB. Die Ladezeit bleibt kurz.
- Neue Oberflächen entstehen schneller und einheitlicher.
- Sobald Pigment CSS stabil ist, wird der Umstieg geprüft. Dann kann `'unsafe-inline'` wieder entfallen.
